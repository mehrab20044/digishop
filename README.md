## 🏢 معرفی پروژه و مجموعه Tiamir

**DigiShop** پروژه توسعه یک پلتفرم فروشگاه اینترنتی برای **Tiamir Digital Marketing** در قزوین است.

این پروژه با هدف ایجاد یک زیرساخت فروشگاهی حرفه‌ای، منعطف و قابل‌استفاده برای کسب‌وکارهای مختلف توسعه داده می‌شود.

هدف DigiShop تنها نمایش محصولات یا ایجاد یک فروشگاه ساده نیست؛ بلکه طراحی یک سیستم کامل برای مدیریت فرایند فروش آنلاین، از معرفی محصول تا ثبت سفارش، پرداخت و مدیریت عملیات فروشگاه است.

معماری این پروژه با توجه به نیازهای یک مجموعه فعال در حوزه دیجیتال مارکتینگ طراحی شده تا بتوان فروشگاه‌هایی با هویت بصری و امکانات متناسب با نیاز هر کسب‌وکار ایجاد کرد.

### چشم‌انداز پروژه

ساخت یک محصول فروشگاهی که سه ویژگی اساسی داشته باشد:

**۱. تجربه خرید حرفه‌ای**

مشتری بتواند محصولات را جست‌وجو کند، مشخصات و تصاویر را مشاهده کند، نسخه موردنظر خود را انتخاب کند و فرایند خرید را به‌سادگی انجام دهد.

**۲. مدیریت ساده و مؤثر**

مدیر فروشگاه بتواند محصولات، موجودی، سفارش‌ها، تصاویر، تخفیف‌ها و تنظیمات فروشگاه را از محیط مدیریتی کنترل کند.

**۳. توسعه‌پذیری برای پروژه‌های تجاری Tiamir**

ساختار سیستم به‌گونه‌ای باشد که امکان سفارشی‌سازی ظاهر، تنظیمات و قابلیت‌ها برای فروشگاه‌های مختلف وجود داشته باشد؛ بدون اینکه برای هر پروژه لازم باشد هسته اصلی از ابتدا بازنویسی شود.

> **DigiShop یک پروژه فروشگاهی در حال توسعه برای Tiamir Digital Marketing است.** قابلیت‌های معرفی‌شده در این مستند بر اساس وضعیت فعلی پیاده‌سازی از امکانات آینده تفکیک شده‌اند.

## 🏗️ معماری نرم‌افزار

معماری DigiShop به‌صورت ماژولار طراحی شده است.

در این ساختار، هر بخش مسئولیت مشخصی دارد و تلاش شده منطق تجاری از نحوه دریافت و پاسخ‌گویی به درخواست‌های API جدا باشد.

### ساختار پردازش درخواست‌ها

```text
                  Client / Frontend
                         |
                         v
                    REST API
                         |
                         v
                 ViewSet / Serializer
                         |
                         v
                   Service Layer
                         |
                         v
                     Django ORM
                         |
                         v
                     PostgreSQL
```

این تفکیک به توسعه‌دهندگان کمک می‌کند بخش‌های مختلف سیستم را مستقل‌تر توسعه دهند، منطق کسب‌وکار را تست کنند و در آینده امکانات جدیدی به فروشگاه اضافه کنند.

### معماری ماژولار

پروژه شامل اپلیکیشن‌های زیر است:

| اپلیکیشن | مسئولیت |
|---|---|
| `products` | مدیریت محصولات، دسته‌بندی‌ها، برندها، مشخصات، تصاویر و تنوع کالا |
| `accounts` | مدیریت کاربران، حساب مشتریان و احراز هویت |
| `cart` | مدیریت سبد خرید |
| `orders` | ثبت و مدیریت سفارش‌ها |
| `seo` | تنظیمات و زیرساخت بهینه‌سازی برای موتورهای جست‌وجو |

اپلیکیشن‌های `accounts`، `cart` و `orders` در حال حاضر ساختار اولیه دارند و قابلیت‌های اصلی آن‌ها هنوز تکمیل نشده است.

# ✅ قابلیت‌های پیاده‌سازی‌شده

## 📦 مدیریت محصولات

DigiShop دارای زیرساخت مدیریت محصولات مبتنی بر Django است.

قابلیت‌های فعلی:

- ایجاد و ویرایش محصولات از طریق Django Admin
- مدیریت دسته‌بندی‌ها
- تعریف برند مستقل برای محصولات
- تعیین قیمت و موجودی
- مدیریت توضیحات کوتاه و بلند
- مدیریت Slug
- فعال و غیرفعال‌کردن محصولات
- مدیریت وضعیت پیش‌نویس و منتشرشده
- ارائه اطلاعات محصولات از طریق REST API

### انتشار محصولات

سیستم از وضعیت‌های زیر پشتیبانی می‌کند:

| وضعیت | توضیح |
|---|---|
| Draft | محصول در حالت پیش‌نویس قرار دارد |
| Published | محصول منتشرشده و آماده نمایش عمومی است |
| Inactive | نمایش عمومی محصول غیرفعال شده است |

محصولات پیش‌نویس یا غیرفعال از API عمومی کاتالوگ حذف می‌شوند.

## 🏷️ مدیریت برند و مشخصات محصول

در DigiShop، برندها و ویژگی‌های محصولات به‌صورت مستقل تعریف می‌شوند.

این ساختار اجازه می‌دهد محصولات متعلق به دسته‌بندی‌های مختلف، مشخصات متفاوتی داشته باشند.

### مثال: موبایل

```text
Product: Galaxy S25

Brand: Samsung
Category: Mobile

Attributes:
  Display: 6.2 inch
  Processor: Snapdragon
  Battery: 4000 mAh
```

### مثال: پوشاک

```text
Product: Cotton Shirt

Category: Clothing

Attributes:
  Material: Cotton
  Fit: Regular
  Sleeve: Long
```

### ویژگی‌های معماری

- امکان تعریف مشخصات قابل‌استفاده مجدد
- ارتباط مشخصات با دسته‌بندی‌ها
- ذخیره مقدار واقعی ویژگی برای هر محصول
- جلوگیری از ثبت ویژگی تکراری برای یک محصول
- اعتبارسنجی سازگاری مشخصات و دسته‌بندی در فرم مدیریتی

این ساختار، پایه‌ای برای پشتیبانی از انواع فروشگاه‌ها در پروژه‌های تجاری Tiamir فراهم می‌کند.

## 🎨 مدیریت تنوع کالا (Product Variants)

یکی از قابلیت‌های مهم DigiShop، پشتیبانی از تنوع محصولات است.

هر محصول می‌تواند دارای چند نسخه قابل‌خرید با شناسه، قیمت و موجودی مستقل باشد.

### مثال

| محصول | رنگ | حافظه | قیمت | موجودی |
|---|---|---|---|---|
| iPhone 16 | مشکی | 128GB | ۶۰ میلیون | ۵ |
| iPhone 16 | مشکی | 256GB | ۷۰ میلیون | ۳ |
| iPhone 16 | سفید | 128GB | ۶۲ میلیون | ۰ |

### قابلیت‌های فعلی

- SKU یکتا برای هر نسخه
- جلوگیری از ثبت ترکیب تکراری رنگ و حافظه
- تعریف قیمت مستقل
- تعریف موجودی مستقل
- فعال یا غیرفعال‌کردن نسخه‌ها
- انتخاب ارزان‌ترین نسخه فعال و موجود به‌عنوان گزینه پیش‌فرض
- ارائه اطلاعات Variantها از طریق API

تمام نسخه‌های یک محصول به موجودیت اصلی همان محصول وابسته‌اند.

مدل فعلی تنوع کالا بر اساس رنگ و حافظه پیاده‌سازی شده و قابلیت توسعه برای انواع دیگر تنوع در ادامه بررسی می‌شود.

## 📊 مدیریت قیمت، موجودی و قابلیت خرید

سیستم دارای قوانین پایه برای تعیین وضعیت قابل‌خرید بودن محصولات است.

در معماری فعلی:

**محصول ساده:** قیمت و موجودی در مدل `Product` نگهداری می‌شود.

**محصول دارای تنوع:** هر نسخه دارای قیمت و موجودی مستقل در مدل `ProductVariant` است.

شرایط پایه قابلیت خرید:

- محصول باید منتشرشده باشد.
- محصول باید فعال باشد.
- قیمت قابل‌استفاده باید معتبر باشد.
- موجودی قابل‌استفاده باید بیشتر از صفر باشد.
- برای محصولات دارای تنوع، حداقل یک Variant فعال و موجود لازم است.

کنترل اتمیک موجودی در فرایند ثبت سفارش و جلوگیری از فروش بیش از موجودی، جزو قابلیت‌های تکمیلی سیستم است.

## 🌐 REST API محصولات

DigiShop از API نسخه‌بندی‌شده برای ارتباط Backend و Frontend استفاده می‌کند.

قابلیت‌های فعلی API:

- دریافت فهرست محصولات
- دریافت جزئیات محصول
- دریافت دسته‌بندی‌ها
- جست‌وجوی محصولات
- فیلتر بر اساس پارامترهای پشتیبانی‌شده
- مرتب‌سازی
- صفحه‌بندی
- دریافت تصاویر، برند و مشخصات
- دریافت تنوع‌های محصول
- دریافت Variant پیش‌فرض
- دریافت وضعیت قابل‌خرید بودن محصول

### آدرس‌های API

| سرویس | Endpoint |
|---|---|
| فهرست محصولات | `GET /products/api/v1/products/` |
| جزئیات محصول | `GET /products/api/v1/products/{id}/` |
| دسته‌بندی‌ها | `GET /products/api/v1/categories/` |
| مستندات Swagger | `GET /docs/` |
| مستندات OpenAPI | `GET /schema/` |

در وضعیت فعلی، API کاتالوگ خواندنی است و مدیریت محصولات از طریق Django Admin انجام می‌شود.

# 🚀 نصب و راه‌اندازی

## پیش‌نیازها

برای اجرای محلی پروژه، ابزارهای زیر موردنیاز هستند:

- Git
- Docker
- Docker Compose

### ۱. دریافت پروژه

```bash
git clone https://github.com/mehrab20044/digishop.git
cd digishop
```

### ۲. تنظیم متغیرهای محیطی

```bash
cp .env.example .env
```

پس از ایجاد فایل `.env`، تنظیمات پایگاه داده و کلید امنیتی Django را متناسب با محیط توسعه تنظیم کنید.

**نکته امنیتی:** فایل `.env` نباید در مخزن Git منتشر شود.

### ۳. اجرای پروژه

```bash
docker compose up -d --build
```

### ۴. اجرای Migrationها

```bash
docker compose exec web python manage.py migrate
```

### ۵. ساخت حساب مدیریت

```bash
docker compose exec web python manage.py createsuperuser
```

پس از ساخت حساب مدیر، می‌توانید از طریق مرورگر به پنل مدیریت دسترسی پیدا کنید.

# 🧪 تست و تضمین کیفیت

در DigiShop تلاش می‌شود تغییرات نرم‌افزار پیش از ثبت در شاخه اصلی از نظر عملکرد و کیفیت بررسی شوند.

ابزارهای مورد استفاده:

**Pytest:** اجرای تست‌های خودکار

**Ruff:** بررسی استانداردهای کدنویسی

**Django Migration Checks:** کنترل هماهنگی مدل‌ها و Migrationها

**GitHub Actions:** اجرای بررسی‌های خودکار در CI

### اجرای تست‌های پروژه

```bash
docker compose run --rm web python -m pytest -q
```

### بررسی کیفیت کد

```bash
docker compose run --rm web python -m ruff check .
```

### بررسی Migrationها

```bash
docker compose run --rm web python manage.py makemigrations --check --dry-run
```

### Continuous Integration

پروژه از GitHub Actions برای بررسی خودکار تغییرات استفاده می‌کند.

[مشاهده وضعیت CI پروژه](https://github.com/mehrab20044/digishop/actions)

تمرکز این پروژه بر ترکیب سه نیاز اساسی کسب‌وکارهای آنلاین است:

**فناوری قابل‌اعتماد، مدیریت کاربردی و تجربه خرید مناسب مشتری.**

از دیدگاه توسعه محصول، DigiShop با هدف ایجاد یک هسته مشترک طراحی شده که بتوان آن را متناسب با نیاز کسب‌وکارهای مختلف شخصی‌سازی کرد.

این رویکرد امکان استفاده از معماری و قابلیت‌های مشترک را در پروژه‌های فروشگاهی آینده فراهم می‌کند.

**DigiShop نمایانگر مسیر توسعه یک محصول فروشگاهی قابل‌ارائه برای پروژه‌های دیجیتال Tiamir است.**
